# Loading-States Fix — P4 Report

## Per-Surface Summary

### Surface 1 — `RecentActivityFeed.tsx`
**Issue:** No loading state; `return null` on error (component vanishes); empty showed on mount before data.  
**Fix:** Added `loading` + `error` state; `finally` sets `loading=false`; error renders `<EmptyState size="sm" icon={ActivityIcon} title="Activity unavailable" ...>` inside the card; empty only renders when `!loading && !error && activities.length === 0`.  
**Test:** 4 cases — loading blocks empty; error shows unavailable (not null, not empty); loaded-zero → empty; data → items rendered.

### Surface 2 — `SurveillanceAlertHistory.tsx`
**Issue:** Empty state rendered even when `error` was set (error banner + "No alerts" together).  
**Fix:** Changed `: alerts.length === 0 ? ...` to `: !error && alerts.length === 0 ? ...`.  
**Test:** 2 cases — error shows only banner (no empty state); loaded-zero shows empty.

### Surface 3 — `audit/page.tsx`
**Issue:** "No verification history yet." rendered alongside the fetch error banner.  
**Fix:** Wrapped the entire table box in `{!error && (...)}` so when error is set, neither the empty state nor the table render (error banner above is sufficient).  
**Test:** 3 cases — error blocks empty; loaded-zero shows empty; data shows table rows.

### Surface 4 — `ai-models/page.tsx`
**Issue:** On fetch error, table showed "No models" alongside the error banner.  
**Fix:** Added `error ?` branch in the table body that renders a `modelsUnavailable` i18n cell, before the `models.length === 0` empty cell.  
**Test:** 2 cases — error shows unavailable cell (not empty); loaded-zero shows empty cell.

### Surface 5a — `inventory/page.tsx` heatmap
**Issue:** On heatmap error, `labs.length === 0` triggered the "No inventory data" empty state.  
**Fix:** Guarded empty with `!error &&`; added `error ? null :` branch (error banner is already shown above).  
**Test:** 2 cases — error blocks heatmap empty state; loaded-zero shows heatmap empty.

### Surface 5b — `inventory/page.tsx` orders tab
**Issue:** `ordersLoading` initialized to `false`; on tab switch there's a render before `fetchOrders` sets loading=true, causing "No purchase orders" flash.  
**Fix:** Added `ordersSettled: boolean` (starts `false`, set `true` in `finally`). Guard: `ordersLoading || !ordersSettled ? loading : !error && orders.length === 0 ? empty : error ? null : table`.  
**Test:** 3 cases — loading shown before settle (no empty flash); error blocks empty; loaded-zero shows empty.

### Surface 6 — `alerts/page.tsx` ClinicalSafetySection
**Issue:** `Promise.all` fetches metrics+reports together; on partial/future failure no distinction between "reports error" vs "genuine zero".  
**Fix:** Split fetches: metrics fetched synchronously (failure → top-level error); reports fetched via fire-and-forget `.then`/`.catch` → `reportsError` boolean. Monthly reports section: `reportsError ? <unavailable EmptyState> : reports.length === 0 ? <empty EmptyState> : <table>`.  
**Test:** 2 cases — reports-only error shows unavailable (not empty); loaded-zero shows empty (not unavailable).

### Surface 7 — `mentorship/page.tsx` PairingDetailPanel
**Issue:** On detail fetch error, `.catch(() => {})` left `detail` as `null`, component returned `null` (row silently collapsed).  
**Fix:** Added `detailError` state; `.catch(() => { setDetailError(true) })`; returns an unavailable `<tr>` row with a "Close" button when `detailError` is true.  
**Test:** 2 cases — error shows unavailable row (not null); success renders detail content.
