Pharmopedia — 3 Architectural Approaches

How does Pharmopedia connect to the rest of the Ultranos ecosystem?

A

Package-Centric — Enhance packages/drug-db

Expand the existing drug-db package into the canonical drug catalog. OPD-Lite, Pharmacy-Lite, and Pharmopedia all read from it. Curation in OPD/Pharmacy writes up to Hub; Hub syncs enriched data back into drug-db for all consumers.

Pros
• drug-db already exists — no new service
• Shared package = one source of truth
• Offline subset already designed for it
Cons
• drug-db becomes very large & complex
• Consumer-friendly content (plain language, media) is awkward in a typed package
• Package rebuild required every drug update
OPD-Lite ──curates──▶ Hub DB ◀──curates── Pharmacy-Lite
                      │
              packages/drug-db (enhanced)
            ┌──────┴──────┬───────────┐
        OPD-Lite  Pharmacy-Lite  Pharmopedia RN
B

Service-Centric — Dedicated Hub Drug Catalog API

A new /drug-catalog service lives in Hub API. This is the canonical store. All three apps sync from it independently. packages/drug-db stays focused on interaction checking only (its original purpose). Pharmopedia syncs the full catalog; OPD/Pharmacy sync relevant subsets.

Pros
• Clean separation — drug-db stays lean
• Hub controls all drug data centrally
• Rich media, multilingual content fits naturally in a DB, not a package
• Each app syncs only what it needs
Cons
• New Hub service to build
• OPD-Lite & Pharmacy-Lite need sync wiring to the new endpoint
OPD-Lite ──curates──▶ Hub /drug-catalog ◀── Pharmacy-Lite
                          │
               sync down (role-scoped)
          ┌──────────┴──────────┬────────────────┐
      OPD-Lite    Pharmacy-Lite    Pharmopedia RN
      (clinical   (formulary       (full catalog)
       subset)     subset)
C

Hybrid — Hub Service + drug-db as Interaction-Only Package

Same as B, but packages/drug-db explicitly stays scoped to interaction checking (its current purpose). Drug content (names, descriptions, media, tiered info) lives in Hub. Pharmopedia syncs content from Hub. OPD/Pharmacy use drug-db for interaction logic and Hub for catalog display. No overlap, no confusion.

Pros
• Clearest boundaries in the codebase
• drug-db stays small & testable
• Content & interaction logic don't bleed into each other
• Easiest to reason about for future devs
Cons
• Same Hub build cost as B
• Slightly more initial wiring across apps
packages/drug-db → interaction checking only (unchanged)

Hub /drug-catalog → full drug content (new)
                │
    ┌───────────┴──────────┬────────────────┐
OPD-Lite    Pharmacy-Lite    Pharmopedia RN
(names+search) (formulary)    (full tiered view)
Recommendation: C — keeps drug-db focused, puts rich content where it belongs (a database, not a compiled package), and gives each app exactly the subset it needs.
