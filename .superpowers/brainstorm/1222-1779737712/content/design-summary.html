Complete Design: Pharmacy Inventory & POS

Full scope summary for approval before spec writing

What We're Building

Transform pharmacy-lite from a dispensing-only tool into a complete pharmacy operations platform: inventory management, procurement, inter-pharmacy transfers, point-of-sale with cash/card/credit, and operational reporting. Progressive complexity via settings toggles ensures corner pharmacies stay simple while hospital pharmacies get full capability.

Architecture Decisions (Locked)

Stock deduction: Immediate local on dispense
Conflict resolution: Movements=Tier1(append), Quantities=Tier2(timestamp)
Catalog source: Hub-managed, locally cached
Barcode: EAN-13 scan + manual fallback
Expiry: FEFO enforced + auto-quarantine expired
Controlled: Running balance + discrepancy reports
Payments: Cash + card + patient credit/tab
Money storage: Integer minor units (no floats)
POS flow: Configurable (mandatory vs flexible post-dispense)
Network: Full cross-pharmacy visibility + transfers
Zones: Opt-in (nullable zone_id on stock)
PO lifecycle: Opt-in (simple receiving by default)

Core Workflows

Dispense (modified):
Scan Rx → Verify → Fulfill → FEFO batch auto-selected → Stock deducted → StockMovement('dispensed') created → Invoice(draft) auto-generated → Confirm → Success + "Collect Payment" CTA (or auto-nav if requirePaymentOnDispense=true)
Receive Stock:
Scan barcode / search catalog → Add items (batch, expiry, qty, cost, selling price) → [if PO mode: select PO, auto-populate expected items] → Confirm receipt → GoodsReceipt created → StockBatches created → StockMovements('received') created → PO status updated
Collect Payment:
Open invoice → Split payment (cash X + card Y + credit Z) → Record each Payment → Update invoice status → [if credit: create LedgerEntry, update PatientAccount.balance] → [if cash: increment CashDrawer.cashIn] → Print/PDF receipt
Stock Count:
Start count (full / spot / controlled-only) → Scan/search items → Enter actual quantities → System shows expected vs actual + variance → Complete count → Auto-generate StockMovement('adjusted') for each variance → Controlled substance variances flagged for review
Inter-Pharmacy Transfer:
View network stock → Request items from sibling pharmacy → [sender approves] → Sender ships (deducts stock, StockMovement('transferred_out')) → Receiver confirms (adds stock, StockMovement('transferred_in')) → Both sync to Hub

Decomposition for Implementation

This is too large for a single spec/plan. Recommended breakdown into 4 sub-projects, each producing working software independently:
Sub-project A: Catalog + Stock Core
CatalogItem sync, StockBatch, StockMovement, Receive Stock (simple mode), Stock Overview page, FEFO, auto-quarantine, dashboard widgets. Dispense integration (deduction).
Sub-project B: POS + Financial
Invoice, Payment, CashDrawer, LedgerEntry, PatientAccount. POS page, cash drawer page, patient accounts page. Dispense → invoice auto-creation. Receipt printing.
Sub-project C: Procurement + Counts
Supplier, PurchaseOrder, GoodsReceipt (full PO mode), StockCount, controlled substance balance. Suppliers page, stock count page. Controlled view upgrade.
Sub-project D: Network + Reports
StockTransfer, Hub stock sync, cross-pharmacy visibility, transfer workflow pages. Reports page (consumption, margins, wastage, aging).
Build order: A → B → C → D (each builds on the previous, but ships independently)
