Brand name search — updated design

Two search paths behave differently for brand names

Offline search (FTS5) — brand names fully supported
FTS5 virtual table indexes four columns:
inn_name · atc_code · brand_names_flat · local_names_flat

brand_names_flat = brand names array joined as space-separated text at sync time.
Searching "Augmentin" → matches the row for Amoxicillin/Clavulanate.

Works fully offline. No schema changes needed.
Online search (API fallback) — brand names NOT yet supported
The Hub API drugCatalog.search endpoint uses PostgREST ILIKE on brand_names TEXT[]. PostgREST cannot ILIKE a text array directly — a generated column is required.

The router already has a comment noting this limitation:
"brand name search requires a future brand_names_text generated column"

The API fallback is only used on first launch before sync completes. Once synced, all searches go through FTS5 locally.
Decision: fix the API gap in Plan 3 or defer?
A

Fix it in Plan 3 — add the generated column migration

Add a brand_names_text TEXT GENERATED ALWAYS AS (array_to_string(brand_names, ' ')) STORED column to drug_catalog in Supabase, add a GIN/trigram index, update the search endpoint. Closes the gap completely.

⭐ Recommended — small migration, clean user experience on first launch too

B

Defer — accept brand name search only works offline

On first launch, brand name searches return no results until sync completes. Add a UI hint: "For best results, sync the catalog." After sync, brand name search works fully via FTS5.
