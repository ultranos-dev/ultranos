Authentication model

Pharmopedia is standalone — who can use it, and do they need to log in?

A

Fully public — no login required

Anyone can browse the drug catalog. No account needed. Appropriate if Pharmopedia is a general patient/public reference tool (like a drug encyclopedia).

Simpler, broader reach. Hub API would need a public/anonymous endpoint.

B

Authenticated — login required

Users must log in (OTP for patients, credentials for clinical staff). Enables role-tiered content (Tier 1/2/3), the enrich endpoint, and pharmacy pricing. Same auth stack as other apps.

⭐ Recommended — aligns with the tier model already built in Plan 1

C

Hybrid — browse public, login for enriched content

Basic drug info (INN name, dose forms, therapeutic class) is visible without login. Clinical details, pricing, and offline sync require a logged-in session.

More complex auth flow and two API code paths to maintain.
