API client + auth

How Pharmopedia talks to the Hub API

src/api/hub-fetch.ts — copied verbatim from Patient Lite Mobile
Certificate-pinned fetch wrapper. Injects Authorization header from auth-store. All API calls go through this. EXPO_PUBLIC_HUB_API_URL env var. No changes — same implementation as patient-lite-mobile.
src/api/drug-catalog.ts — tRPC-style REST client
search(q, lang, limit)
GET /trpc/drugCatalog.search?input=… → DrugSearchResult[]
getByAtcCode(atcCode)
GET /trpc/drugCatalog.getByAtcCode?input=… → DrugEntryTier1|2|3
sync(sinceVersion, limit)
GET /trpc/drugCatalog.sync?input=… → { entries, latestVersion }
getPrices(atcCode, lat, lng, sort, limit)
GET /trpc/drugCatalog.getPrices?input=… → PharmacyPrice[]
enrich(atcCode, fields)
POST /trpc/drugCatalog.enrich → DrugEntryTier1|2|3
src/store/auth-store.ts — zustand
token: string | null -- memory only, never persisted
user: { sub, role, facilityId? } | null
login(credentials) → calls Hub auth endpoint, stores token
logout() → clears token, clears SQLite drug_catalog, redirects to (auth)/login
refreshToken() → uses refresh token (httpOnly cookie) to get new access token
Login screen — two flows on one screen
PATIENT: Phone number → OTP → token
Clinical staff: Username + password → token (+ TOTP if MFA enabled)

Toggle between flows via a segmented control. Same screen, two form states.
